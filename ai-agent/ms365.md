# MS 365 MCP Server

Rules for calling tools exposed by `@softeria/ms-365-mcp-server`. The server maps ~300 tools 1-to-1 to Microsoft Graph endpoints, plus utilities (`download-bytes`, `get-download-url`, `get-upload-url`, `upload-attachment-from-file`, `parse-teams-url`) and auth helpers (`login`, `verify-login`, `list-accounts`, `select-account`, `remove-account`). Tool names are `kebab-case`; `endpoints.json` is the source of truth for every tool's `pathPattern`, `scopes`, `presets`, and `llmTip`.

## 1. Discover tools before calling them

- In `--discovery` mode, the call order is **`search-tools` → `get-tool-schema` → `execute-tool`**. Skipping `get-tool-schema` is the #1 cause of Graph 400s. `search-tools` is BM25 over tool name + llmTip + description + path; query with 2–4 short keywords (`send email`, `list unread mail`, `download drive file`). If it returns nothing, retry with shorter or different keywords.
- Outside discovery mode, tool names are the Graph endpoint aliases (`list-mail-messages`, `send-mail`, `get-calendar-view`, `create-onedrive-folder`). Read the tool's description and every parameter description — the server ships spec-gap guidance there (e.g. `$expand` only accepts navigation properties, `$top` is a page size not a row limit).
- Prefer `--preset <name>` at server startup rather than having the LLM guess. Presets: `mail`, `calendar`, `files`, `personal`, `work`, `excel`, `contacts`, `tasks`, `onenote`, `search`, `users`, `outlook` (app-scoped), `onedrive` (app-scoped), `teams` (app-scoped), `teams-write` (send-only). `work`, `users`, `teams`, `teams-write` require `--org-mode`. `download-bytes` and `download-bytes-to-file` ride with every preset except `teams-write`.

## 2. The canonical call template

Every Graph tool call has this shape. Path and query params go at the **top level** of `arguments`; the request body goes **under the key `body`**:

```

{
"name": "<tool-alias>",
"arguments": {
"<pathParam>":   "<value>",           // e.g. "messageId"
"<queryParam>":  "<value>",           // e.g. "select", "top", "filter"  (no $ prefix needed)
"body":          { /* the JSON Graph would accept */ },
"confirm":       true,                // only if the confirm gate is on AND user approved
"account":       "user@company.com"   // only in multi-account stdio mode
}
}

```

**Three rules that fix 90% of failures:**

1. **Path params are NOT inside `body`.** `{"messageId": "AAMk...", "body": {...}}` — never `{"body": {"messageId": "AAMk..."}}`.
2. **The path param name is the tool's declared name, not `id`.** `get-mail-message` wants `messageId`, not `id`. Copy the exact name from `get-tool-schema`. Kebab-case and camelCase both resolve, but `id` does not.
3. **The body is exactly what Graph would accept** — do not wrap it, do not flatten it. The server repairs flattened bodies (#569) and misplaced itemBodies (#620) in some cases, but those are repairs, not the contract.

### Mandatory discovery sequence (`--discovery` mode)

If the server runs with `--discovery`, you **cannot** call a Graph tool by name directly. The only callable tools are `search-tools`, `get-tool-schema`, `execute-tool`, plus utilities. The sequence is non-negotiable:

```

1. search-tools({ query: "send email" })
→ returns [ { name: "send-mail", ... }, ... ]
2. get-tool-schema({ tool_name: "send-mail" })
→ returns parameter list with names, types, required, description
3. execute-tool({ tool_name: "send-mail", parameters: { body: {...} } })

```

Inside `execute-tool`, everything that would have gone in `arguments` goes under `parameters`:

```

{
"name": "execute-tool",
"arguments": {
"tool_name": "send-mail",
"parameters": {
"body": { "message": { "subject": "...", "toRecipients": [...] } }
}
}
}

```

Note the shape shift: `get-tool-schema` says `body` is the request body; `execute-tool` takes it under `parameters.body`.

## 3. Account and identity

- With multiple MSAL accounts cached, every tool gains an `account` parameter; pass the account's email (`user@company.com`). Call `list-accounts` first if you do not know the exact spelling. With one account it auto-selects.
- **`account` does not work in HTTP/OAuth mode** (bearer-token-per-request): the server refuses it with a message pointing at the bearer identity. Under `--obo` or plain `--http`, do not pass `account`; the connecting client's bearer is the identity.
- Under HTTP/OAuth, do not attempt to switch identity mid-session. Reconnect the client as the desired account instead.
- `--trust-proxy-auth` HTTP mode falls back to MSAL cache, so `account` works there.
- Pinned mode (`MS365_MCP_EXPECTED_USERNAME` / `MS365_MCP_EXPECTED_HOME_ACCOUNT_ID`) collapses to single-account: no `account` param, no switching.
- `list-accounts` intentionally hides `homeAccountId` — use the CLI for exact IDs.
- `--logout` clears all cached accounts including the pinned one. `remove-account <id>` is the surgical option.

## 4. Query parameters — OData rules

- **Never combine `$filter` with `$search`** on the same request. The server refuses with `invalid_query_parameter`.
- `$select` takes a comma-separated string (`id,subject,from`) or a string array; the server normalizes both. Always `$select` on list endpoints — Graph returns whole resources by default and the response will blow context.
- `$top` is a **page size**, not a row limit. Start at 5–15. Use `fetchAllPages: true` to follow `@odata.nextLink` (default cap 100 pages / 10,000 items, configurable via `MS365_MCP_MAX_PAGES` / `MS365_MCP_MAX_ITEMS`). Use the returned `@odata.nextLink` for manual paging via `skiptoken`.
- `$expand` **only accepts navigation properties** (e.g. `attachments`, `singleValueExtendedProperties`). Expanding a non-navigation property like a message body fails with "Parsing OData Select and Expand failed". Some APIs accept only one relationship — prefer a single value.
- `$orderby` takes `field asc|desc`. `$count=true` enables advanced query mode and is required for complex `$filter` on `flag`/`flagStatus` or `contains()`.
- Some endpoints accept fewer query params than the schema advertises. `list-joined-teams`, `list-my-associated-teams`, `list-chats`, `list-channel-messages`, and the calendar delta tools accept a restricted set. `list-joined-teams` and `list-my-associated-teams` accept **no** query params.

### Mail `$search` (KQL)

For `/me/messages` and `/users/{id}/messages`, `$search` is Outlook KQL, not OData. The server auto-repairs quoting, but write it correctly to avoid relying on the repair:

- Wrap the **whole** expression in **one** pair of double quotes: `$search='"from:john AND subject:meeting"'`.
- Do NOT quote each clause: `'"from:john" AND subject:meeting'` is a 400. The server unwraps and re-wraps, but treat this as a fallback.
- For a property phrase, keep the quotes inside: `$search='"subject:\"quarterly report\""'`.
- Empty/whitespace-only `$search` is refused with `invalid_search`. Pass a real query or omit `$search`.
- Directory search on `/users` and `/groups` uses the **opposite** convention — quote each clause, no outer pair: `'"displayName:john" OR "displayName:jane"'`. Directory search also needs `ConsistencyLevel: eventual`; the server sets this for `list-users` automatically.

## 5. Copy-paste examples by family

### Read one message

```

{ "name": "get-mail-message",
"arguments": { "messageId": "AAMkAGI2...", "select": "id,subject,from,body,receivedDateTime" } }

```

❌ `"arguments": { "id": "AAMkAGI2..." }` — wrong param name.
❌ `"arguments": { "body": { "messageId": "AAMkAGI2..." } }` — path param in the body.

### List messages

```

{ "name": "list-mail-messages",
"arguments": {
"select": "id,subject,from,toRecipients,receivedDateTime,bodyPreview,isRead,hasAttachments",
"top": 10,
"filter": "isRead eq false"
} }

```

❌ `"$top"` / `"$select"` — the `$` is optional but the bare form is cleaner.
❌ `"filter": "...", "search": "..."` — the two cannot be combined.
❌ `"select": "body"` on a listing — use `bodyPreview`; fetch the full body only via `get-mail-message`.

### Search messages (KQL)

```

{ "name": "list-mail-messages",
"arguments": { "search": ""from:john AND subject:meeting"", "select": "id,subject,from,receivedDateTime" } }

```

The whole expression is one pair of double quotes. Do not quote each clause.

### Create a draft / send mail

```

{ "name": "create-draft-email",
"arguments": {
"body": {
"subject": "Status update",
"body": { "contentType": "text", "content": "Here is the update." },
"toRecipients": [ { "emailAddress": { "address": "alice@contoso.com" } } ]
}
} }

```

❌ `"arguments": { "subject": "...", "toRecipients": [...] }` — the server merges flattened fields into `body`, but this is a repair, not the contract.

### Reply / forward

```

{ "name": "reply-mail-message",
"arguments": { "messageId": "AAMk...", "comment": "Looks good, shipping it." } }

```

❌ Do not build the reply body yourself — Graph adds quoting, history and recipients server-side.

### Create a calendar event

```

{ "name": "create-calendar-event",
"arguments": {
"body": {
"subject": "Standup",
"start": { "dateTime": "2026-10-20T09:00:00", "timeZone": "UTC" },
"end":   { "dateTime": "2026-10-20T09:30:00", "timeZone": "UTC" },
"attendees": [ { "emailAddress": { "address": "bob@contoso.com" }, "type": "required" } ]
}
} }

```

❌ `"startDateTime": "..."` — times are nested objects, never flat fields.
❌ For a **recurring** event, do not use UTC — use the organizer's own zone name (from `get-mailbox-settings`) or DST will drift it.

### Send a chat message with a mention

```

{ "name": "send-chat-message",
"arguments": {
"chatId": "19:abc@unq.gbl.spaces",
"body": {
"body": {
"contentType": "html",
"content": "Hi <at user-id="11111111-2222-3333-4444-555555555555">Jane Doe</at>, ready?"
}
}
} }

```

❌ `"body": { "contentType": "html", "content": "..." }` — this is the **itemBody**, not the chatMessage. The chatMessage has its own `body` field.

### Download a drive file

```

{ "name": "get-download-url",
"arguments": { "target": "/me/drive/items/01ABCDEF.../content" } }

```

Then fetch the returned `downloadUrl` with **no** Authorization header. For mail attachments and other `$value` byte endpoints use `download-bytes` (base64) or `download-bytes-to-file` (writes to a local path, stdio mode only).

### Download a mail attachment

```

{ "name": "download-bytes",
"arguments": { "target": "/me/messages/AAMk.../attachments/AAMk.../$value" } }

```

❌ `"target": "https://..."` — targets are **relative Graph paths**, must start with `/`.

### Batch

```

{ "name": "graph-batch",
"arguments": {
"body": {
"requests": [
{ "id": "1", "method": "GET",  "url": "/me/messages?$top=5" },
{ "id": "2", "method": "POST", "url": "/me/sendMail",
"headers": { "Content-Type": "application/json" },
"body": { "message": { "subject": "x", "toRecipients": [] } } },
{ "id": "3", "method": "GET",  "url": "/me/messages/AAMk...", "dependsOn": ["1"] }
]
}
} }

```

❌ `"url": "https://graph.microsoft.com/v1.0/me/messages"` — sub-request URLs are relative to the version root.
❌ A write sub-request with no `Content-Type` header. The server fills it in for object bodies but you should set it yourself.

### Paginate a list

```

{ "name": "list-mail-messages",
"arguments": { "select": "id,subject,receivedDateTime", "top": 25, "fetchAllPages": true } }

```

❌ Passing a giant `top` instead. `top` is a **page size**, not a row limit.

## 6. Body-shape cheat sheet

The single most common failure is misidentifying what the request body *is*. These are the actual shapes:

| Tool | Body shape |
|---|---|
| `send-mail` | `{ message: { subject, body: {contentType,content}, toRecipients }, saveToSentItems }` |
| `create-draft-email` | `{ subject, body: {contentType,content}, toRecipients, ccRecipients }` |
| `update-mail-message` | `{ isRead, categories, flag, importance }` (draft edits add `subject`/`body`/`toRecipients`) |
| `reply-mail-message` / `reply-all-mail-message` / `forward-mail-message` | `{ comment, toRecipients? }` |
| `create-calendar-event` | `{ subject, start: {dateTime,timeZone}, end: {...}, attendees, location, body }` |
| `send-chat-message` | `{ body: { contentType, content }, mentions? }` — the outer `body` is the chatMessage, the inner is the itemBody |
| `send-channel-message` | Same as `send-chat-message` |
| `create-onedrive-folder` | `{ name, folder: {}, '@microsoft.graph.conflictBehavior': 'rename' }` |
| `update-excel-range` | `{ values: [[...]] }` — one inner array per row |
| `create-todo-task` | `{ title, dueDateTime, body, checklistItems: [{displayName, isChecked}] }` |
| `create-planner-task` | `{ planId, bucketId, title, assignments }` (use `update-planner-task` with `If-Match` for edits) |

## 7. Common operations and pitfalls

### Mail
- `list-mail-messages`: `$select=id,subject,from,toRecipients,receivedDateTime,bodyPreview,isRead,hasAttachments`. Use `bodyPreview`, not `body`, for listings.
- `get-mail-message`: fetch full body by id.
- `create-draft-email` / `send-mail`: toRecipients is `[{emailAddress:{address}}]`. **Resolve addresses with `list-users` first** — do not invent SMTP addresses.
- Attachments under 3 MB: `add-mail-attachment` with `@odata.type: '#microsoft.graph.fileAttachment'`, `name`, `contentBytes` (base64). 3 MB–150 MB: `create-mail-attachment-upload-session` then PUT bytes yourself. Under 3 MB on the upload-session path returns `ErrorAttachmentSizeShouldNotBeLessThanMinimumSize`.
- Reply/forward: use `reply-mail-message` / `reply-all-mail-message` / `forward-mail-message` with `comment`. Do NOT reconstruct the body — Graph handles quoting and history.
- `create-reply-draft` / `create-reply-all-draft`: passing `Message.body` replaces the whole draft body and drops quoted history. Do not combine `comment` and `Message.body` — 400.

### Calendar
- Times are **nested objects**: `start: {dateTime, timeZone}`, `end: {dateTime, timeZone}`. Never flat `startDateTime` / `startTimeZone`.
- UTC is safest for one-off events. For recurring events use the organizer's own timezone name — Graph resolves DST against `start.timeZone`, so UTC drifts after DST changes.
- `get-calendar-view` expands recurring occurrences; `list-calendar-events` returns only the series master. Use the view tool for date-range queries.
- Teams meeting join URL is `onlineMeeting.joinUrl` (the event resource has no `joinWebUrl`). `isOnlineMeeting` and `onlineMeetingProvider` are not `$filter`-able (400) — filter client-side.
- Setting `attendees` replaces the whole list. Include everyone, not just the new attendee.
- Deleting a series master deletes **all** occurrences; delete a specific instance id to cancel one occurrence.

### Teams
- **Mentions**: write `<at user-id="<aad-guid>">Display Name</at>` in `body.content` (HTML) and the server numbers the tag and builds `mentions`. Use the `userId` field from `list-team-members` / `list-chat-members`, not `id`. The shorthand needs `contentType: 'html'`.
- Hand-built form (only if the shorthand fails): `body: {contentType: 'html', content: 'Hi <at id="0">Name</at>'}` plus a top-level `mentions: [{id: 0, mentionText, mentioned: {user: {id, displayName, userIdentityType: 'aadUser'}}}]`. `userIdentityType: 'aadUser'` is required or Graph 400s.
- `list-chats` accepts only `$filter`, `$top` (max 50), `$expand`, `$orderby=lastMessagePreview/createdDateTime desc`. `$search` and ordering by `lastUpdatedDateTime` return 400.
- `list-chat-messages` `$top` is capped at 50; `$orderby` only descending on `createdDateTime` / `lastModifiedDateTime`.
- Channel/channel-reply/chat message send: prefer `contentType: 'html'`; plain text is often mangled.
- Preset `teams-write` is send-only: send/reply in chats and channels, list chats/teams/channels by name, activity notifications. It carries no message-reading tools and no byte downloaders.

### Files / OneDrive / SharePoint
- **Large drive/SharePoint file content**: prefer `get-download-url`. Returns `@microsoft.graph.downloadUrl` — a pre-authenticated URL you fetch with NO Authorization header. Also supports server-minted URLs for mail attachments, meeting recordings, etc. when the server runs with `--enable-attachment-urls`.
- **Everything else** (mail attachments, profile photos, Teams hosted content, meeting recordings): `download-bytes` returns base64. In stdio mode (or HTTP with `--http-local-file-tools`), `download-bytes-to-file` writes to a local absolute path instead.
- `get-download-url` requires a driveItem path. Mail/event attachments end `/$value` and are minted only when the feature is on; meeting recordings end `/content`. Anything else is refused with a message naming `download-bytes`.
- Upload: `upload-file-content` takes a base64 body (server decodes). For anything but small files use `create-upload-session` — the caller PUTs the bytes. Truncated base64 writes a truncated file with no error.
- New-file addressing: `/items/root:/path/to/file.txt:/content`. `@microsoft.graph.conflictBehavior: 'rename'|'replace'|'fail'` controls name collisions.
- `search-onedrive-files` `q` searches names, metadata, and content.

### Excel
- Excel tools never require a formal table — `update-excel-range` sets values/formulas on any range. Use `{values: [[...]]}` with one inner array per row.
- `format-excel-range` sets alignment/wrap/columnWidth/rowHeight. Font, fill, borders use `format-excel-range-font` / `format-excel-range-fill` / `format-excel-range-border` (one border side per call).
- `get-excel-used-range` finds the populated bounds before appending.
- Cell styling often encodes meaning — `get-excel-range-format` with `$expand=font,fill,borders` to interpret it.

### To Do / Planner
- Planner updates need `If-Match` with the ETag from a prior `get-planner-task` with `includeHeaders: true`. Without it: 412 Precondition Failed.
- To Do `$select` is **not supported** on `list-todo-task-lists`, `list-todo-tasks`, `get-todo-task` — 400. Omit it.
- To Do checklist items: use `create-todo-checklist-item` / `update-todo-checklist-item` / `delete-todo-checklist-item`. Graph 400s `checklistItems` in a PATCH on the task.
- Priority on Planner is 0–10, lower = higher. UI presets: 1=Urgent, 3=Important, 5=Medium, 9=Low.

### Batch
- `graph-batch` combines up to 20 Graph sub-requests in one HTTP call. Body: `{requests: [{id, method, url, headers?, body?, dependsOn?}]}`. URLs are relative to the version root (`/me/...`, `/drives/...`), never absolute.
- Responses come back in arbitrary order — match by `id`.
- **Write sub-requests need a `Content-Type` header on the body.** The server fills it in for object bodies, but a string body (base64) is left to you. Batch validation failures 400 the whole batch.
- Sequence dependent writes with `dependsOn: ['1']`.

## 8. Params that cannot be combined or misused

- `$filter` + `$search` → `invalid_query_parameter`
- `$search` + `$orderby` on mail → 400 from Graph
- `$select` on `list-todo-tasks`, `list-todo-task-lists`, `get-todo-task` → 400
- `$filter` on `isOnlineMeeting` / `onlineMeetingProvider` → 400 (filter client-side)
- Any query param on `list-joined-teams` / `list-my-associated-teams` → dropped
- `top > 50` on `list-chats`, `list-chat-messages` → 400
- `$orderby` ascending on `list-chat-messages` → 400
- `checklistItems` in a PATCH on a To Do task → 400 (use the `*-todo-checklist-item` tools)
- `$expand` on a non-navigation property → "Parsing OData Select and Expand failed"

## 9. Write safety

- When the server is started with `MS365_MCP_REQUIRE_CONFIRM=true`, destructive tools (POST except `readOnly`, PATCH, PUT, DELETE) return `{error: 'confirmation_required'}` until re-invoked with `confirm: true`. Call once to learn the shape, then confirm only after the user has approved the action.
- `--read-only` mode blocks all writes (POST not flagged `readOnly`, PATCH, DELETE). `find-meeting-times`, `get-schedule`, `search-query`, `get-mail-tips`, `copilot-retrieve`, `get-presences-by-user-id`, `get-onenote-notebook-from-web-url`, `set-my-presence` are read-only POSTs and still register.
- These tools **do** send, delete, or mutate. Never call them in an autonomous loop without an explicit user approval step: `send-mail`, `send-draft-message`, `reply-mail-message`, `reply-all-mail-message`, `forward-mail-message`, `create-shared-mailbox-reply-draft` (when followed by send), `send-chat-message`, `send-channel-message`, `reply-to-channel-message`, `send-my-activity-notification`, every `delete-*`, `update-mail-message`, `update-event`, `move-mail-message`, `move-shared-mailbox-message`, `share-drive-item`, `create-drive-item-share-link`, `set-my-presence`, `set-my-user-preferred-presence`.
- `send-draft-message` sends an existing draft as-is; if the signoff feature is on, drafts written through the server carry it, drafts written in Outlook do not.

## 10. Errors and recovery

| Error | Meaning | Fix |
|---|---|---|
| `invalid_query_parameter` | Endpoint does not support that OData option | Run `get-tool-schema`; drop or rename the param |
| `invalid_search` | `$search` had no searchable text | Supply a real KQL expression, or omit `$search` |
| `invalid_skiptoken` | Cursor value had no `$skiptoken` or `$skip` | Use `fetchAllPages: true` instead, or the bare `@odata.nextLink` |
| `confirmation_required` | Confirm gate is on | Re-call with `confirm: true` after approval |
| `user_fields_restricted` | Byte tool pointed at a user-profile path under the field boundary | Use `list-users` instead |
| `403 ... requires organization mode` | Server is personal-mode, tool is org-scoped | Restart server with `--org-mode` |
| `circuit_open` | 5 consecutive Graph failures tripped the breaker | Back off; do not retry in a loop |
| `AADSTS70011` under `--obo` on personal accounts | Token request lost the scope | Server sends `<clientId>/access_as_user offline_access`; do not work around it |
| `AADSTS700025` (public client secret rejected) | Public-client redirect_uri | Server retries without the secret automatically |
| `429` / `503` / `504` | Transient throttling / upstream | Retried by the server with backoff + circuit breaker |

## 11. Anti-patterns (each one causes a specific, reproducible failure)

- Passing path params inside `body` → Graph 404 on a literal `{messageId}` segment.
- Passing `id` where the schema wants `messageId` → same 404.
- Quoting each clause of a mail `$search` → server repairs it, but the repair is not the contract.
- Passing `body` as `{contentType, content}` on a tool whose schema expects `body.body` → server repairs it only when the outer schema has a `body` field; on other tools it 400s.
- Inventing SMTP addresses or user GUIDs → Graph 404 or sends to the wrong person. Resolve with `list-users` / `list-team-members` / `list-chat-members`.
- Rebuilding a reply body by hand → loses the quoted thread and formatting. Use the Graph action tools.
- Passing `attendees` on an event PATCH to add one person → replaces the whole list. Read, append, PATCH.
- Fetching `body` on a listing → blows context. Use `bodyPreview`.
- Passing a full URL as a `target` → the tools take relative Graph paths.
- Calling `get-download-url` on a mail attachment metadata path (not `/$value`) → returns the `/$value` hint; append `/$value` or use `download-bytes`.
- Setting `top` to `1000` on a list → the server clamps or Graph 400s. Use `fetchAllPages: true`.
- Passing `$select`/`$top` to endpoints that do not advertise them.
- Calling `send-*` or `delete-*` in a tight loop; the Graph circuit breaker opens after 5 consecutive failures.

## 12. Quick workflow

1. `search-tools({ query: "<2–4 keywords>" })` — e.g. `"send email"`, `"list unread mail"`, `"download drive file"`, `"excel range"`.
2. Read the returned tool's description and `llmTip` — they contain the exact conventions.
3. `get-tool-schema({ tool_name })` — read every parameter's `required`, `in` (Path / Query / Body / Header), and description.
4. Build the `parameters` object exactly per the schema: path and query at the top level, body under `body`.
5. `execute-tool({ tool_name, parameters })`.

Do not skip steps 2 and 3. The server's parameter descriptions are the contract; the model's guesses are not.
